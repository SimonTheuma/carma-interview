# ADR-0020: Upload endpoint requires a shared token supplied as a secret

## Context and problem statement
The app has no authentication. The upload route is its first write endpoint and indirectly spends LLM budget (ADR 0010). Architect 0002 D3.

## Considered options
1. Shared upload token from a secret file, constant-time compare (chosen)
2. No auth

## Decision outcome
Chosen option 1. `UPLOAD_TOKEN_FILE` is generated by `ops/init-secrets.sh` like the other secrets, mounted into web only, sent as a bearer header, and never logged or committed.

**Superseded by ADR-0037** (2026-10-28): PoC upload is open when `UPLOAD_ENABLED`; the brief does not require auth.

### Consequences
- Good: writes and spend are not open to anyone reaching the port.
- Bad: token handling in the UI; one shared secret, no per-user identity (P9 attribution limited to batch_id).
- Risks: FP-9 token leakage.

### Confirmation
Tests for 401 on missing or wrong token and log scrubbing.
